Atividade 3
História 1 - Avaliação do pedido

História de usuário:

Como cliente, quero avaliar o pedido depois da entrega, para ajudar outros clientes a escolherem melhor.

Critérios de aceitação
Dado que o pedido foi entregue, quando o cliente abre o app, então aparece a opção de avaliar o pedido.
Dado que o cliente avalia com nota e comentário, quando confirma o envio, então a avaliação aparece no perfil do restaurante.
Requisitos não funcionais

RNF 1 - Usabilidade

A opção de avaliação deve ser apresentada de forma clara e fácil de localizar após a entrega do pedido.

Característica ISO/IEC 25010: Usabilidade.

RNF 2 - Confiabilidade

O sistema deve garantir que a avaliação enviada pelo cliente seja registrada corretamente e permaneça disponível no perfil do restaurante.

Característica ISO/IEC 25010: Confiabilidade.

RNF 3 - Compatibilidade

A funcionalidade de avaliação deve funcionar corretamente nos dispositivos e sistemas operacionais suportados pelo aplicativo.

Característica ISO/IEC 25010: Compatibilidade.

História 2 - Salvar cartão de pagamento

História de usuário:

Como cliente, quero salvar um cartão de pagamento, para não digitar os dados a cada compra.

Critérios de aceitação
Dado que o cliente cadastra um cartão válido, quando confirma o cadastro, então o cartão fica disponível para escolha no checkout.
Dado que o cliente tem um cartão salvo, quando faz um novo pedido, então pode selecionar esse cartão sem redigitar os dados.
Requisitos não funcionais

RNF 1 - Segurança

Os dados do cartão salvo devem ser protegidos contra acesso não autorizado durante o armazenamento e utilização pelo sistema.

Característica ISO/IEC 25010: Segurança.

RNF 2 - Usabilidade

O cadastro e a seleção de um cartão salvo devem ser realizados de forma simples, clara e com poucos passos.

Característica ISO/IEC 25010: Usabilidade.

RNF 3 - Confiabilidade

O sistema deve manter os cartões cadastrados disponíveis para seleção no checkout, desde que estejam válidos e não tenham sido removidos pelo cliente.

Característica ISO/IEC 25010: Confiabilidade.

História 3 - Resumo diário de vendas

História de usuário:

Como dono de restaurante, quero ver um resumo diário de vendas, para acompanhar o desempenho do dia.

Critérios de aceitação
Dado que o dia comercial termina, quando o restaurante abre o painel de vendas, então vê o total de pedidos e o faturamento do dia.
Dado que o restaurante seleciona um período diferente, quando aplica o filtro, então o resumo é recalculado para aquele período.
Requisitos não funcionais

RNF 1 - Eficiência de desempenho

O painel de vendas deve apresentar o resumo de pedidos e faturamento em até 3 segundos após o acesso ou aplicação de um filtro.

Característica ISO/IEC 25010: Eficiência de desempenho.

RNF 2 - Usabilidade

O resumo de vendas deve apresentar o total de pedidos e o faturamento de forma clara e organizada para facilitar a interpretação dos dados.

Característica ISO/IEC 25010: Usabilidade.

RNF 3 - Adequação funcional

O sistema deve recalcular corretamente o total de pedidos e o faturamento de acordo com o período selecionado pelo restaurante.

Característica ISO/IEC 25010: Adequação funcional.
